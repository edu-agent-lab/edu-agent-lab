## 4. 필터 설계

### 필드별 성격

| 필드 | 값 수 | 채워짐 | 필터로 | 메모 |
|---|---|---|---|---|
| `school_level` | 4 | 100% | **필수** | 추출 쉽고(정규식), 틀리면 치명적 |
| `subject` | 26 | 100% | **필수** | 별칭 매핑 필요 (아래) |
| `doc_type` | 4 | 100% | 조건부 | 질의 성격에서 유추, 불명확하면 비움 |
| `grade_band` | 15 | 58% | 보류 | 표기 정규화 선행 (아래) |
| `course` | **816** | 100% | 명시할 때만 | 사용자가 정확히 말할 확률 낮음 |
| `area` | 767 | 58% | 쓰지 않음 | 사용자가 영역명을 모른다 |
| `section`/`top`/`sub` | 4/8/14 | 17% | 쓰지 않음 | doc_type 내부 구분 |

### `subject` 별칭 매핑이 필요하다

사용자가 쓰는 말과 데이터 값이 다르다.

| 사용자 표현 | 데이터 값 |
|---|---|
| 통합사회, 한국사, 세계사, 지리, 경제, 정치 | `사회` (course가 그것) |
| 윤리, 생활과 윤리, 현대사회와 윤리 | `도덕` |
| 기술가정, 기술·가정 | `기술·가정` (가운뎃점 주의) |
| 실과 | `실과(기술 · 가정)/정보` (공백 포함 주의) |
| 통합과학, 물리, 화학, 생명과학, 지구과학 | `과학` |
| 바슬즈, 바른생활 | `바른 생활, 슬기로운 생활, 즐거운 생활` |

프로젝트 1 `apps/notion-search/search.py`의 `_subject_key()`가 같은 문제(`공통 영어1` vs `공통영어1`)를
공백·숫자 제거로 풀었다. 같은 방식 + 별칭표로 충분하다. 26개라 손으로 쓸 수 있는 규모다.

### `grade_band`는 표기가 깨져 있다

같은 학년군이 4가지로 흩어져 있다 — 그대로 필터로 쓰면 걸러진다.

```
[초등학교 3~4학년]    [초등학교 3∼4학년]     <- 물결표가 다르다 (U+007E vs U+223C)
[중학교 1~3학년]      중학교 1~3학년         <- 대괄호 유무
고등학교 공통과목(1학년)
고등학교 선택과목(2~3학년)
```

쓸모는 있다 — "초등 5학년"에서 `초3-4`를 빼고 `초5-6`만 남길 수 있다. 다만 2순위.

### hard vs soft — hard를 쓴다

조건에 안 맞는 레코드를 **배제**(`score = -inf`)할지 **감점**(`score *= 0.5`)할지.

| 필터 필드 | 적용 | Top-1 | R@3 | R@10 | 메타 | 통과 |
|---|---|---|---|---|---|---|
| 없음 | – | 7/13 | 0.55 | 0.68 | 0.65 | 7/22 |
| `level` | hard | 8/13 | 0.61 | 0.73 | 0.78 | 10/22 |
| `level+subject` | hard | 10/13 | 0.65 | 0.76 | 0.95 | 13/22 |
| `+doc_type` | hard | 10/13 | 0.70 | 0.80 | 0.95 | 13/22 |
| **전부(+course)** | **hard** | **11/13** | **0.72** | **0.85** | **1.00** | **14/22** |
| 전부 | soft | 11/13 | 0.72 | 0.85 | 0.98 | 13/22 |

재현: `python eval_ncic.py --compare-filters`

읽을 것 세 가지:

1. **필터가 성능의 절반이다.** 없으면 7/22, 다 걸면 14/22.
2. **`level` -> `+subject`에서 가장 크게 뛴다** (10 -> 13).
3. **hard >= soft.** soft는 메타가 1.00 -> 0.98로 떨어지고 통과도 하나 줄었다. 조건을 어긴
   레코드가 상위에 끼어들기 때문이다.

조건에 맞는 후보가 충분하면 hard와 soft의 결과는 **같다**. 갈리는 건 후보가 없을 때다:

```
Q: "초등학교 환경 보호 수업"  (초등학교 + 환경 = 0건)
hard:  결과 없음
soft:  1. 특수교육 교과/영역  2. 초등학교/과학  3. 초등학교/과학  4. 초등학교/사회   <- 전부 조건 위반
```

**hard를 택하는 이유**는 프로젝트 1과 같다 — 조건을 어긴 결과를 내놓으면 사용자가 그게
틀렸는지 모른다. 교육과정 근거 검증이 목적인데 "초등 과학 성취기준으로 만든 초등 환경
수업계획안"은 가장 나쁜 실패다. 0건은 눈에 보이는 실패이고, 멀티턴이라 사용자가 고칠 수 있다.

프로젝트 1도 같은 결정을 두 번 했다 — 데이터셋에 없는 과목은 전부 제외(`search._passes_filters`),
검색 결과 없음은 유사 추천 없이 안내만(README "방식 B").

### 추출 실패를 soft로 때우지 않는다

`subject="생활과 윤리"`처럼 추출이 틀리면 hard에서는 0건이 난다. 이건 soft로 가릴 문제가
아니라 **별칭표로 풀 문제**다. 0건일 때 추출한 조건을 함께 보여주면 사용자가 "도덕이야"라고
고칠 수 있다.
