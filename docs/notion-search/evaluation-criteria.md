# "좋은 검색"과 "좋은 요약"의 평가 기준 (Day2 Step4 → Day6 확정)

> 상태: **확정** (Day6). 골든셋 21건 전체(`eval.py --classify`)로 실측한 결과를 아래에 반영했다.

## 좋은 검색의 기준 — 확정

- **정확도/재현율/노이즈**: `eval.py`가 계산하는 세 지표(재현율=기대 결과를 놓치지 않았는지,
  정확도=군더더기가 없는지, 노이즈=`must_not` 페이지가 섞였는지) 그대로 채택. 별도 N값은
  두지 않는다 — 골든셋 항목별 기대 결과 건수가 1~7건으로 편차가 커서 고정 N이 의미가 없고,
  "기대 결과 전부 포함 + 노이즈 0"을 PASS 기준으로 삼는 게 더 명확했다.
- **제목 매칭**은 별도로 `expect_top`(1위가 정확히 그 페이지인지)까지 확인한다.

## 좋은 요약의 기준 — 확정

- **길이**: 2~3문장. `prompt.py`의 `SUMMARIZE_PAGE_PROMPT`와 일치.
- **핵심 정보 누락 없음**: 자료 유형 + 다루는 주제 + (있으면) 대상 학년·목적을 반드시 포함.
- **원문 왜곡 없음**: 원문에 없는 내용, 특히 **숫자(문항 수·건수 등)를 지어내지 않는지**를
  Day6에서 실제로 검증 항목에 추가했다 — 아래 "프롬프트 튜닝" 참고.

## Day6 프롬프트 튜닝 기록

### ① 요약 — 문항 수 할루시네이션

- **발견**: "과학 퀴즈" 페이지(실제 문항 수 3개: 객관식1 + 서술형2)를 요약시켰더니
  "총 4개의 문항"이라고 없는 숫자를 지어냄. 3회 재현 시 4개/5개/4개로 매번 다른 숫자가 나옴.
- **1차 시도(실패)**: "숫자는 셀 수 있을 때만 쓰세요"로 조건부 허용 → 여전히 4개/5개로 틀림.
  경량 모델(HCX-DASH-002)은 지시만으로 실제 개수 세기 자체를 못 함.
- **2차 시도(채택)**: 개수 언급 자체를 금지("본문에 세어야 알 수 있는 숫자는 언급하지 마세요.
  본문 안에 숫자가 이미 적혀 있을 때만 옮겨 쓰세요") → 3회 재현 모두 숫자 없이 정확한
  내용(핵심 개념 목록 등)으로 대체됨. 세는 능력을 못 고칠 거면 그 화법 자체를 피하는 쪽이 확실하다.
- **본문이 통째로 빈 페이지**는 프롬프트 지시로 안 막히고, 제목만 보고 내용을 완전히
  지어내는 걸 확인했다(예: "빈 페이지 테스트"라는 제목만 줬더니 있지도 않은 수업 활동을
  서술함). 그래서 `summarizer.py`에 **LLM 호출 자체를 막는 코드 가드**를 추가했다 —
  본문이 비면 "본문이 비어 있어 요약할 수 없습니다"를 바로 반환하고 LLM을 부르지 않는다.
- **모델 전환 후 재검증(CLOVA → OpenAI gpt-5-mini)**: 위 기록은 HCX-DASH-002 기준이라
  모델이 바뀐 뒤 같은 테스트를 다시 돌렸다. "과학 퀴즈" 3회 재현 모두 개수 표현 없이
  개념 위주로 요약했고, 빈 본문(`""`, `<empty-block/>`) 둘 다 코드 가드에 걸려 LLM을
  부르지 않았다. **2차 시도의 프롬프트 규칙과 코드 가드 모두 그대로 유효하다.**

### ② 분류 — 속성 필터 누락 + type 오분류

- **발견**: "3학년 수학 중 지난달 자료"에서 LLM이 명시된 `subject`("수학")를 빼먹고,
  `type`도 스펙에 없는 "grade"라는 값을 지어냄. 데이터셋에 해당 학년/기간 자료가 없어
  최종 결과(0건)는 우연히 맞았지만, 분류 자체는 틀린 상태였다.
- **1차 시도(실패, 회귀 발생)**: "type은 keyword/title/filter 중 하나만" + "5개 키를 항상
  다 포함"이라는 지시문을 추가 → subject 누락은 고쳐졌지만, 멀쩡하던 골든셋 케이스
  "퀴즈 자료 찾아줘"가 오히려 깨짐(`keyword="퀴즈"`로 잘 나오던 게 `null`로 바뀜).
  `eval.py --classify` 점수가 21/21 → 19/21로 떨어진 걸 보고 원인을 역추적해 롤백했다.
- **2차 시도(채택)**: 지시문 대신, "filter" 분류 기준 옆에 학년+과목+날짜가 전부 언급된
  질의의 완성된 예시 하나를 추가했다(세 필드를 전부 채운 형태로). 이 프로젝트 프롬프트들이
  이미 확인해온 패턴대로 — "~하지 마세요"류 지시보다 완성된 예시가 이 모델엔 더 잘 먹힌다.
  결과: subject 누락도 고쳐지고 "퀴즈" 회귀도 없이 21/21 유지.
- **부수 효과**: 이 예시에 "지난달"의 정확한 날짜 계산(단일 개월, 07-01~07-31)을 포함시켰더니,
  별개로 발견했던 "지난달"이 2개월 범위로 계산되던 버그도 같이 없어졌다.

## 노이즈 케이스 테스트 (Day6 Step3)

골든셋에는 없는 케이스로 안정성만 확인한다. 정답이 정해진 게 아니라 "에러 없이 합리적으로
동작하는지"를 본다.

| 케이스 | 질의 | 결과 |
|---|---|---|
| 오타 | "토룬 수업 자료 찾아줘" | LLM이 오타를 보정해 `keyword="토론 수업"`으로 분류, 5건 정상 반환 |
| 애매한 질의 | "수업 자료 좀 보여줘" | 필터·키워드가 둘 다 비어 14건 전체 반환. **정책 결정(Day6): 별도 경고 없이 이대로 유지** — "질의가 모호합니다" 안내보다, 있는 자료를 다 보여주는 편이 실사용에는 더 낫다고 판단 |
| 존재하지 않는 페이지 | "5학년 우주여행 수업계획안 찾아줘" | 0건, "검색 결과가 없습니다" 정상 노출 |
| 복합 속성 필터 | "3학년 수학 중 지난달 자료" | 프롬프트 튜닝 후 학년·과목·날짜 조건 모두 정확히 반영. 데이터셋에 해당 자료가 없어 0건 |
